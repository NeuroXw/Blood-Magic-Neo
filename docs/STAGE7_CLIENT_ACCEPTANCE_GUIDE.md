## 2. 启动之前：建立一个可复现的测试环境

1. 在启动器中建立专用的 Minecraft 26.1.2 + NeoForge 26.1.2.122 实例，起名例如 `BMNeo-beta验收`。
2. 使用启动器的“游戏目录 / 打开实例文件夹”功能，找到**这个实例实际使用的游戏目录**。下文把它称为 `<游戏目录>`。记下绝对路径。
3. 关闭该实例，把上述 JAR 复制到 `<游戏目录>\mods\`。确保其中只保留一份 `bloodmagic` 模组；阶段 3～6 的旧包、上游旧版 Blood Magic 都不要同时放入这个验收实例。
4. 第一轮使用 NeoForge 和本 JAR 的最小组合，资源包使用默认，着色器关闭。先验证基础表现，再用同一个测试世界的副本测试日常模组组合。
5. 记录：Windows 版本、显卡型号/驱动、Java 版本、游戏分辨率、窗口/全屏、GUI 缩放、语言、NeoForge 版本及其他模组列表。
6. 创建新的创造模式超平坦测试世界，启用命令，命名 `BMNeo-beta-验收-日期`。不要用唯一一份长期存档；本版也不提供 1.20.1 旧世界转换。
7. 开局选中文（简体），先用 GUI 缩放 2；若分辨率不允许，选一个界面完整可见的档位并记录。
8. 在空地划分祭坛区、炼金阵区、机器区、仪式区，每区相隔约 16 格。仪式区留足上下空间，熔岩测试区用石材围住。
9. 测试时保持世界在运行。单人游戏打开暂停菜单会影响计时；“10 秒”均按正常 20 tick/s 估算，卡顿时可以更久。

可选的开局命令，每次一行：

```text
/gamemode creative
/difficulty normal
/time set noon
/weather clear
/spawnpoint
```

### 祭坛视觉修复后的优先复测

完整退出Minecraft后替换JAR并重新启动；只按F3+T不能加载修改后的Java渲染代码。方块ID未变，可以在原测试存档中直接检查已有祭坛。

1. 空祭坛应为原版黑灰色底座、凹槽和红色角柱，不能仍是空白符文的整块立方体；背包/手持祭坛也应显示相同模型。
2. 在日光下分别放石头、铁砧、钻石和空白石板，确认能辨认本来的材质颜色，物品不再像黑色剪影，且围绕祭坛上方中心旋转。
3. 在夜晚和有火把的室内比较：物品应随环境变暗、变亮，不是永远满亮。
4. 打开GUI取出物品，悬浮显示应消失；保存重进后模型和物品显示正确。
5. 若仍异常，保留新JAR的SHA-256、完整游戏画面和同次运行的latest.log，尤其记录是否有资源包/渲染模组。

## 5. 祭坛 GUI、鼠标和合成（A01～A08）

### A01：先打开一个完全空的祭坛

1. 在空地放祭坛，主手切到空格，副手也清空，松开潜行键后右键。
2. 预期 GUI 有一个祭坛槽、玩家背包和快捷栏；标题、等级、合成状态、进度和 LP 清晰可读。
3. 新祭坛初始等级为 1，容量 10,000 LP。红色条和文本不能跑出底板，也不能盖住可点击槽位。
4. 鼠标分别移动到祭坛槽、玩家物品、LP 区域、进度条。高亮应落在鼠标指向的格子，物品及数值提示可读。

**这里没有“开始合成”按钮**，有匹配原料和 LP 就会自动处理。若手上拿着物品，右键会尝试插入；潜行空手右键则献祭，不会开 GUI。

### A02：一次完整的石板合成与世界渲染

1. 先保持创造模式，关闭界面，潜行空手右键空祭坛 5 次。没有加成符文时应累计 1,000 LP。
2. 持 1 个原版石头 `minecraft:stone`，不潜行右键空祭坛。
3. 观察祭坛上方：应出现槽内物品并缓慢旋转，位置随祭坛固定。绕行、俯视、贴近和退后观察，不应漂到相邻方块、穿过很远的地面或一直残留旧物品。
4. 切空手右键开 GUI。配方为石头 → 空白石板，消耗 1,000 LP，基础速率 5 LP/tick，约 10 秒完成。
5. 进度应前进，LP 应下降；最终同一个槽变成 1 个空白石板、LP 为 0。取出后世界上悬浮的物品也应消失。
6. 改用生存模式放入一个石头，确认手中少 1 个；创造模式世界右键插入不扣手持数量，不能用它检验物品守恒。

### A03：点击、Shift、数字键和满背包

使用没有配方的泥土做纯点击测试，避免原料在操作中变成产物。取物后切生存模式；每个子项前清空祭坛槽。

| 操作 | 验收标准 |
|---|---|
| 左键把泥土放入 / 取出 | 实际槽位与点击位置一致；关界面重开物品还在正确位置 |
| 鼠标持 8 个泥土，右键祭坛槽 | 放入 1 个，光标剩 7 个 |
| Shift 点击背包中的一组泥土 | 可转入祭坛槽，数量守恒 |
| Shift 点击祭坛内一组泥土 | 转回有空间的玩家背包 |
| 鼠标指向祭坛槽，按对应快捷栏数字键 | 与指定快捷栏槽交换，不复制、不消失 |
| 背包全部占满且无兼容空位，再 Shift 取物 | 物品留在祭坛，不被吞掉 |
| 只留一个能接收少量泥土的未满堆叠，再 Shift 取物 | 仅可容纳的部分转移，其余保留 |
| 点击后立刻 Esc，再重开 | 结果与关闭前一致，光标物品正常回收或按原版规则处理 |

点击后等待约一秒仍回弹到旧位置，属于需要记录的同步问题。先保存视频，不要一直快速点同一格导致无法还原第一次操作。

### A04：缺 LP、错误原料与等级不足

- 新祭坛仅加 200 LP，放 1 个石头。先前进、LP 用尽后显示“缺少 LP”，进度会按配方退回；补 LP 后能继续。这不是一个会永久保存全部缺血进度的配方。
- 放泥土并等待，应该不产出石板、不扣 LP。
- 在一级祭坛放空白石板，即使有足够 LP 也不应变强化石板；它要求二级。
- 看 GUI 时切换物品、关闭重开，应及时刷新，不能仍显示上一个已移除原料的进度。

### A05：献祭生命的行为

切生存、满血、无吸收心或防护效果，祭坛未满且没有正在消耗 LP 的原料。潜行空手右键一次：正常损失 2 点生命（1 颗心），祭坛增加 200 LP。受伤无敌时间可能让连续快速点击无效；每次间隔约 1 秒再核对。

生命不超过 2 点（1 颗心）时不再献祭；祭坛满时也不扣血。恢复生命后再继续其他项目。祭坛内的 LP 与玩家灵魂网络的 LP 是两份余额，祭坛满不代表网络已充满。

### A06：二级结构与加成

把祭坛自身坐标当 `(0,0,0)`。在它**下方一层 y=-1** 放 3×3 的外围 8 个空白符文，中心无需符文：

```text
y=-1 顶视图；C 是祭坛正下方，R 是符文
R R R
R C R
R R R
祭坛在 C 的上一层，即 y=0。
```

1. 等约 1 秒或重新交互，GUI 应显示等级 2；拆掉任意必需符文应降为 1，放回后恢复 2。
2. 用 2,000 LP 合成 1 个空白石板 → 强化石板，约 20 秒。高级祭坛可能继续处理产物；想保留低级石板应及时取走，当前每次完成后约有 30 tick 间隔。
3. 在正交位置 `(1,-1,0)` 换入 1 个增容符文，容量应从 10,000 变成 12,000。初次做此项时先把 LP 保持在低位，避免容量变化影响比较。
4. 正交位置换为牺牲符文，创造模式单次自我献祭基数应从 200 增到 220；换回空白符文恢复。
5. 正交位置放一个速度符文，石头配方速率应从 5 提到 6 LP/tick，所需总 LP 仍为 1,000。

二级结构的四角符文参与完整性判断，但仅四个正交位置提供加成。不要把四角没有加成报成鼠标或同步错误。

### A07：更高等级（扩展验收，建议完成）

所有坐标仍相对祭坛。下一级结构保留此前所有部件；“±”表示所有正负组合。

| 等级 | 追加结构 |
|---|---|
| 3 | y=-2：`(±3,-2,i)` 与 `(i,-2,±3)`，i=-2..2，共20符文；四角 `(±3,y,±3)`，y=-1..0 用实心方块，y=1 顶部用荧石 |
| 4 | y=-3：`(±5,-3,i)` 与 `(i,-3,±5)`，i=-3..3，共28符文；四角 `(±5,y,±5)`，y=-2..1 用实心方块，y=2 用血石砖或大血石砖 |
| 5 | y=-4：`(±8,-4,i)` 与 `(i,-4,±8)`，i=-6..6，共52符文；四角 `(±8,-4,±8)` 放狱锻块 `bloodmagic:dungeon_metal` |

每升一级，用 GUI 或占卜印记确认；再拆一个本级新增部件，确认降级，再复原。当前五级顶石使用狱锻块；不要照旧教程摆原版信标。六级晶体标签默认为空，六级不在本版正常通过标准中。

### A08：缩放、窗口与长数值

分别在 GUI 缩放 1、2、3、自动（界面能容纳的档位）检查 A01/A03，窗口和全屏各一轮；改分辨率后重新打开 GUI。中文字不能盖住槽位，血量条和鼠标热区不能偏移。高容量祭坛的数值要完整且不能变成负数。记录每个失败组合的“窗口分辨率 + 缩放 + 语言”，不要只记“界面歪了”。

## 6. 血球、网络与费用（N01～N04）

### N01：给后续测试准备网络余额

1. 创造模式拿一个学徒气血宝珠 `apprenticebloodorb`，对空气右键。
2. 悬停物品应看到绑定者是你，等级 2、容量 25,000 LP。每次右键最多给自己的网络补 200 LP。
3. 拿占卜印记对空气右键，快捷栏上方应显示你的网络 LP。消息会消失，数值比较时截图或录像。
4. 继续用血球对空气右键充能。只做满泉建议至少 2,000 LP；三种仪式加机器全套建议补到约 20,000 LP。拿到了高级血球不等于自动充满。
5. 把祭坛槽清空，注入 LP，再放入已绑定血球。祭坛 LP 应减少，网络 LP 应增加；弱球/学徒球基础转移速率为 2/5 LP 每刻。网络满后祭坛不再白白损失 LP。

| 血球等级 | 容量 | 基础祭坛充能速率 |
|---|---:|---:|
| 1 虚弱 | 5,000 | 2 LP/tick |
| 2 学徒 | 25,000 | 5 LP/tick |
| 3 法师 | 150,000 | 15 LP/tick |
| 4 大师 | 1,000,000 | 25 LP/tick |
| 5 术士 | 10,000,000 | 50 LP/tick |

高阶血球可以在低阶祭坛充能；必须先右键绑定。祭坛配方优先于血球充能。

### N02：绑定持久化

已绑定血球放箱子、取出、丢出捡回、退出重进，绑定者不变；印记和激活水晶也检查一次。不要把未绑定物品的“未绑定”提示判成损坏。多人借用行为见第 13 节。

### N03：生存费用与生命替代

费用验证前切生存模式，并暂停其他耗 LP 的机器、仪式和祭坛充能。每次使用先后都用同一枚绑定自己的占卜印记读取网络。

- 网络足够：功能印记扣自己的绑定网络余额；不应扣生命。
- 网络不足：本版保留不足的网络余额，改扣使用者完整费用对应生命。每 100 LP 向上取整为 1 点生命。例如水印记网络只剩 50 LP 时，成功使用应保留 50 LP，扣 1 点生命（半颗心）。
- 不能安全支付生命时，动作不执行。请在新测试世界、低风险位置观察；不要混入回血、吸收心、伤害免疫效果来做精确数值比较。
- 炼金台和仪式不会用玩家生命替代不足的网络费用；余额不足时暂停。
- 创造模式跳过印记费用和仪式激活费，因此“创造模式 LP 没扣”不是费用失效。机器处理和仪式持续效果仍须核对其实际资源要求。

### N04：范围与隔离

同一世界跨维度的网络应相同；可以通过正常下界传送门往返后读取。新建另一个世界，同名玩家不应继承上一世界余额。不要更换启动器账号或离线身份后期待 UUID 绑定不变。

## 7. 炼金阵：先看渲染，再做六种配方（R01～R05）

### R01：空阵与材料显示

1. 用完整石块铺一块平台，顶面上方保持空气。拿奥术灰烬，右键石块顶面。
2. 预期出现贴近地面的阵纹；它不是一个 GUI 方块。普通空手右键无界面是正常行为。
3. 在晴天和较暗处分别看，检查俯视、低角度、四个方向；不应是紫黑图案、整块不透明黑板、巨大跨区块平面或随镜头漂移。
4. 先右键放红石，再放空白石板。阵中应显示两个材料；匹配配方后应采用对应阵纹并有旋转表现。
5. 等约 200 tick（10 秒），地上生成 1 个占卜印记，阵消失。拾取确认 ID 正确；不应同时还掉原材料，或一直连续出产物。

**关键拍摄方式**：开始录屏 → 展示手中材料 → 绘阵 → 放第一个材料 → 绕到侧面 → 放第二个材料 → 拉远看完成。阵会很快消失，所以出现渲染异常时视频比单张完成后截图更有用。

### R02：六配方逐个验收

每行重新画一个阵，严格先放第一材料、再放第二材料。可从创造栏直接拿材料来隔离“渲染/配方”问题，完整生存链另测。

| 第一材料 | 第二材料 | 预期产物 |
|---|---|---|
| 原版红石粉 | 空白石板 | 占卜印记 |
| 水之试剂 `reagentwater` | 空白石板 | 水之印记 |
| 熔岩试剂 `reagentlava` | 空白石板 | 熔岩印记 |
| 虚空试剂 `reagentvoid` | 强化石板 | 虚空印记 |
| 风之试剂 `reagentair` | 强化石板 | 风之印记 |
| 视界试剂 `reagentsight` | 强化石板 | 先知印记 |

全部默认约 10 秒；这六条阵配方直接费用为 0 LP，相关费用已在祭坛和炼金台环节支付。没有网络 LP 也能做默认阵配方，不应报成免费合成漏洞。

### R03：错误顺序与取回

先放石板、后放红石，等待约 12 秒，不应出占卜印记。潜行空手右键取回后放的材料，再右键取回先放的材料；顺序改正后重新开始。材料取回应重置原进度，不能继续享受之前错误配方的进度。

### R04：支撑、耐久和材料守恒

切生存，用一份新奥术灰烬连续绘阵，耐久应消耗，最多绘制 20 次。创造不消耗不能用于此项。向阵放入不匹配的两种材料，再打掉下方支撑，阵应移除、每份材料只掉一次；关游戏再进不能重复掉。没有完整支撑顶面时绘阵失败，应记录具体方块类型，先用完整石头复查。

### R05：重进、重载和距离

做一条阵配方，在约 3 秒时正常保存退出，重进后应继续并只产出一次。对空阵和未完成阵做一次资源重载（确认按键后可用 F3+T）并截图；资源重载用于客户端贴图，`/reload` 用于服务端数据包，两者不能互相替代。远离到区块离开模拟范围再返回时不要求离线推进，但回来后应恢复显示和合成。

## 8. 炼金台：双格结构、槽位、扣费与返桶（T01～T05）

### T01：摆放和双格 GUI

1. 清出至少 3×3 空地，摆一个炼金台。它占相邻两格，只拥有一套库存。
2. 分别从北/南/东/西方向摆一张，检查两半连接、不重叠、不只剩一半。
3. 先点这半放入材料，关掉再点另一半；应看到同一库存。
4. 左边为 3 列×2 行共 6 个原料槽；中右上单槽是血球槽；最右偏下单槽是输出；下方显示网络 LP、状态和进度。
5. 输出槽不允许手工放物品，右键它没放进去不是点击失效。血球槽只接收血球，不接收普通材料。

### T02：先做一份奥术灰烬

1. 给自己的网络充至少 1,000 LP；拿一颗已经右键绑定的一级或以上血球。
2. 六原料槽中分别放红石、白色染料、火药、煤，各 1 个，余下两槽留空。把血球放专用槽。
3. 等约 10 秒。输出应为 1 份奥术灰烬，四种原料各消耗 1 个；血球留下且绑定不变；网络只在完成时扣 500 LP。
4. 合成时关界面再打开，应继续；查看另一半的 GUI 也一样。
5. 普通点击、右键、Shift 转移、数字键交换、满背包取出按 A03 的方法重复测试。尤其检查 Shift 点击血球是否进入专用槽。

### T03：全部六条机器配方

**同一种材料出现两次就分占两个原料槽**；例如两根羽毛放在同一格的堆叠不能替代两格。除表中材料外，其他原料槽清空。所有配方均约 10 秒。

| 产物 | 每格各放一个的材料 | 最低血球 | 完成扣费 |
|---|---|---:|---:|
| 奥术灰烬 | 红石、白色染料、火药、煤或木炭 | 1 | 500 LP |
| 水之试剂 | 糖、水桶、水桶 | 1 | 300 LP |
| 熔岩试剂 | 熔岩桶、红石、圆石、煤块 | 1 | 1,000 LP |
| 虚空试剂 | 空桶、线、线、火药 | 2 | 1,000 LP |
| 风之试剂 | 恶魂之泪、羽毛、羽毛 | 2 | 2,000 LP |
| 视界试剂 | 荧石粉、玻璃、玻璃、占卜印记 | 1 | 500 LP |

水配方完成后应返还 2 个空桶，熔岩配方返还 1 个空桶，检查原料格及附近掉落；清理返还桶后再换配方。视界试剂会消耗占卜印记，不是把它当作保留工具。六条各做一次的费用合计 5,300 LP。

### T04：停机原因能看懂

在已经放对原料的前提下依次测试：

| 条件 | 预期 |
|---|---|
| 不放血球 / 放未绑定血球 / 血球等级太低 | 提示需要绑定血球／意志；不会偷偷扣费出物 |
| 血球正确，但余额不足 | 提示 LP／意志不足，等待充值后恢复 |
| 输出已被前一件不可堆叠产物占用 | 提示输出槽已满；不扣 LP、不吞原料 |
| 原料错误、少放或多放无关材料 | 不合成；可能显示“就绪”，该文字不保证配方已匹配 |

做“输出满”可把第一次产出的奥术灰烬留在输出，再准备下一份；不要试图手工往输出槽塞测试物品。

### T05：拆除与漏斗

生存模式下在原料槽放已数好的物品、血球槽放一球，用合适镐拆任意一半。两半都应消失，总共只回收一张桌子和一套库存。再单独建一张桌，用漏斗从上/侧向**持有库存的主半块**输入原料、底部提取产物；副半块不要求提供库存接口。血球槽手动管理，漏斗不承担自动放球。重复材料仍须保持分槽条件，普通漏斗不等于完整自动配料系统。

## 9. 地狱熔炉与恶魔意志（F01～F05）

### F01：GUI 与零意志的区别

地狱熔炉是单个方块，不需要额外外壳。左侧 2×2 是四原料槽，中右上是意志槽，右下是输出。进度、状态、两位小数意志值应可读；按 A03 复测点击、Shift 和满背包。

从创造栏拿到的恶魔意志和结晶默认是 **0 意志**。物品存在不等于含有能量，放入零值物品后停机属于正常资源不足。

### F02：真实获取与投掷物渲染

1. 在普通难度、带遮阳顶的小围栏内生成一只僵尸，准备简易灵魂陷阱与武器。
2. 对准僵尸投掷灵魂陷阱。应能看见投掷物，不应出现紫黑方块、残影或抛出即崩溃。
3. 命中后在约 15 秒内击杀它（捕获效果持续 300 tick）；捡起原始恶魔意志，悬停应显示正的小数值。一次未成功先核对是否命中和及时击杀，不要把扔空算作掉落错误。
4. 将原始意志放进背包，手持空结晶对空气右键；意志应转入结晶，总量不增加，空掉的原始意志应消失，结晶满后保留溢出来源。
5. 退出重进，再看小数与进度条，数值不能变负、丢失或突然满容量。

### F03：固定数值配方测试

为了不用反复刷怪，可在这个命令已开启的测试世界生成固定资源样本：

```text
/give @s bloodmagic:basemonstersoul[bloodmagic:demon_will=5.25d]
/give @s bloodmagic:soulgempetty[bloodmagic:demon_will=64.0d]
/give @s bloodmagic:soulgemlesser[bloodmagic:demon_will=240.0d]
```

先看悬停数值确认样本正确，再开始计费。若命令输入变红，截图完整命令和错误提示；也可以用 F02 的正常转移积累资源，命令解析问题不能直接证明机器配方坏了。

| 配方 | 四原料槽各放一个 | 门槛 / 消耗 | 无其他意志来源时的预期 |
|---|---|---|---|
| 微弱结晶 | 红石、金锭、玻璃、青金石 | 至少1 / 消耗1 | 意志专用槽放5.25原始意志；完成后该槽剩4.25，输出空微弱结晶 |
| 次级结晶 | 含64意志的微弱结晶、钻石、红石块、青金石块 | 至少60 / 消耗20 | 意志专用槽留空；输出次级结晶含44意志 |
| 普通结晶 | 含240意志的次级结晶、钻石、金块、灌输石板 | 至少240 / 消耗50 | 意志专用槽留空；输出普通结晶含190意志 |

每次约 100 tick（5 秒）。升级结晶放在原料槽，保留的剩余意志进入输出结晶；不要同时放其他意志来源再套用这张表的精确余量。三个容量分别为 64 / 256 / 1,024。

### F04：不足与输出堵塞

微弱结晶升级时，总意志为 59 即使大于消耗 20 也不能合成，因为门槛是 60。门槛和实际消耗不同。输出留着一颗结晶再尝试第二次：应暂停、不扣意志、不吃材料。取走输出后才能继续。

### F05：漏斗、拆除与保存

上面/侧面漏斗输入原料，下面漏斗提取输出；意志槽手动放置。生存模式拆掉有材料和意志的熔炉，核对方块和库存只掉一套。做合成约 2 秒时正常退出并重进，结果只能产生一次、只扣一次意志。

## 10. 六种印记的实际效果（S01～S06）

先给网络充能，切生存模式，使用前后都用绑定自己的占卜印记读数。准备石头围出的独立水槽、熔岩槽、干燥台阶以及平坦安全跑道，暂停其他耗费。

| 编号 | 操作 | 预期效果与费用 |
|---|---|---|
| S01 占卜 | 对空气右键；再指祭坛右键 | 空气显示绑定者网络；祭坛显示等级和 LP；不把印记塞入祭坛、不收费 |
| S02 先知 | 对有配方的祭坛右键 | 显示祭坛数据，聊天里有进度及输入/输出缓冲数值；无费用。缓冲槽尚未迁移传输，显示0可以正常 |
| S03 水 | 对槽底顶面右键一次 | 生成水源，扣100 LP；另对可含水的干燥台阶测试，台阶保留且含水 |
| S04 熔岩 | 对石材槽底右键 | 生成熔岩源，扣1,000 LP；不要让流体进入其他测试装置 |

水与熔岩印记需要可放置目标；对纯空气挥动不生成远处流体不是故障。已存在相同源流体时不应重复收费。下界水行为受环境影响，先以主世界测试为基准。

## 11. 仪式：从零搭建到激活（I01～I06）

### I01：共同准备与工具使用

1. 三个仪式分别建，核心之间至少相隔 12 格。核心坐标统一记为 `(0,0,0)`；最好搭高一点，便于从下方接近核心和检查结构。
2. 准备主仪式石、普通或暮色仪式占卜棒、弱效激活水晶、足够空白仪式石、已绑定且充过能的血球及占卜印记。
3. 占卜棒对空气右键会**轮换**仪式，查看快捷栏上方“已选择：…”消息，直到明确显示目标名称。新棒初始选择满泉，但第一次空中右键会切到下一项，不能只凭“新拿的棒”猜选择。
4. 对主仪式石逐次右键，每次只放或改一块元素石。创造可直接搭；生存需要背包有空白仪式石，正确搭满后额外点一次应显示“符文完整，请使用激活水晶”。
5. 普通棒只能选满泉、绿林；采掘需要暮色仪式占卜棒。占卜棒是物品工具，主仪式石才是方块核心。
6. 首先对空气右键弱效激活水晶并检查绑定者。用自己的绑定水晶右键核心激活；潜行右键核心停止。仪式没有单独 GUI，不以是否打开界面判断成功。
7. 放好结构、备足 LP 后，切生存模式做激活费验证。若核心已经被上方方块盖住，可以从下方接近核心；不要误点周围元素石。

### I02：满泉仪式——第一项必做

结构为核心同一高度的四角水之仪式石：

```text
y=0 顶视图：W=水之仪式石，M=主仪式石，.=空气
W . W
. M .
W . W
```

1. 占卜棒选满泉，对核心逐点搭齐四角。核心正上方 `(0,1,0)` 留空气。
2. 在 `(±1,1,0)` 和 `(0,1,±1)` 放石头围壁，形成只容纳中央水源的小槽，避免流到别区。
3. 网络充到至少 2,000 LP，停止其他耗费，读出起始值 L。切生存，用水晶右键核心。
4. 预期显示“仪式状态已更新”，核心上方生成水源。首次激活扣500 LP，首次产水再扣25 LP，所以效果发生后的读数应为 **L−525**。
5. 等10秒不取水，余额应不再因这个仪式下降。拿桶取走水，核心应补一个新水源，再扣25 LP。
6. 用水晶潜行右键核心停止，再用桶取水，应不再补水。停止不退激活费。
7. 再次正常激活需要重新支付500 LP。对已经激活的核心反复正常右键不应重复收激活费。

这项同时验证结构、绑定、网络、世界效果和客户端同步，比只看到一条“激活成功”消息更可靠。

### I03：绿林仪式

```text
y=0 顶视图：E=地之仪式石，W=水之仪式石
E W E
W M W
E W E
```

1. 用占卜棒选绿林，搭齐8块符文。保持能接近核心，例如从下方点击。
2. 在核心上方一层 y=1 铺3×3耕地，作物位于 y=2；摆足光源，附近放水保持耕地湿润。使用小麦、胡萝卜、马铃薯等原版普通作物。
3. 网络至少6,000 LP，生存激活时扣5,000 LP。短时间内可能已有生长扣费，因此用录像记录激活瞬间或先激活再播种。
4. 观察数分钟：区域内作物能生长；每个实际成功生长事件扣20 LP。每20 tick只是尝试，概率不保证一秒长一段；一次周期可能影响多个作物。
5. 全部成熟时，不应继续为空效果扣费。拔掉其中一株重种，再看能否继续帮助生长。
6. 单独记录土壤、光照、作物位置和观察时间；自然随机生长也存在，不能只看一株恰好长了就断言仪式工作，结合网络扣费和停止后的对照判断。

### I04：采掘仪式

需要暮色棒、16块符文。相对核心结构：

| 层 | 坐标 / 元素 |
|---|---|
| y=0 | `(±1,0,0)`、`(0,0,±1)` 为地 |
| y=0 | `(±2,0,0)`、`(0,0,±2)` 为火 |
| y=0 | `(±2,0,±2)` 四角为暮色 |
| y=1 | `(±2,1,0)`、`(0,1,±2)` 为风 |

1. 把核心架高，在它正上方放一个空箱子；核心下方 y=-1、-2 先保持空气，方便从下面点到核心。
2. 在 y=-3 的3×3范围放9个石头作为精确样本，其余目标范围保持空。更低处留安全地面；玩家不要站在将被挖走的方块上。
3. 网络至少6,000 LP，生存激活，扣5,000 LP。预期约每40 tick（2秒）最多挖一块，箱子收到圆石。
4. 九块石头全部完成后，应得到9个圆石；总效果费用63 LP，连激活共 **5,063 LP**。空范围不应持续扣费。
5. 在范围外放一块对照石头，不能被挖。范围为相对核心 x/z=-1..1、y=-3..-1，不是朝前一大片矿场。
6. 用基岩、带方块实体的箱子、流体等做跳过测试；不得强拆这些受排除的对象。箱子满或不存在时，产物可掉在核心上方，不能当成“必须全部存箱”的承诺。

### I05：暂停、停止、损坏和资源不足

优先用满泉做容易观察的对照：

| 动作 | 预期 |
|---|---|
| 核心正下方放红石块，让核心受电；取走上方水源 | 暂停补水，不扣效果费用；不要把受电时首次激活失败误判成水晶坏了 |
| 移除红石块 | 继续工作，不重收激活费；新产水仍扣25 |
| 拆掉一块必需符文 | 仪式停用，不再产生效果 |
| 把符文补回 | 需要手动重新激活，不能假设自动恢复 |
| 网络余额低于单次效果费用 | 暂停效果，不扣玩家生命；补足后继续 |
| 激活前余额低于激活费 | 生存模式激活失败、不应扣一部分后丢失 |
| 水晶潜行右键核心 | 主动停止；与红石暂停区分，随后再激活要交激活费 |

没有专门的网络编辑命令。余额不足可用新测试世界只充200 LP、正常消耗，或在已有世界按读数控制；无需手改存档。

### I06：失效信息与视觉检查

失败消息“请检查符文、拥有者、红石信号和网络 LP。”是汇总提示；记录消息后按这四项逐一核对。普通棒选不到采掘、核心被遮住、拿熔岩水晶代替激活水晶、以及创造激活后网络为0导致无持续效果，是需要先排除的情况。

检查各元素石贴图是否对应、坐标是否正确、远近切换或重进后结构是否一致。本版没有承诺上游全部仪式动画；不能把没有华丽粒子单独算作核心效果失败。

先完成单机。若有第二台机器/第二个玩家，双方和服务端使用同一 JAR、MC 与 NeoForge 版本；至少做一次真实客户端连接独立服务端。局域网集成服务器可以补充检查，但不能替代独立服务端覆盖。

| 项目 | 两人具体操作 | 验收标准 |
|---|---|---|
| M01 同看祭坛 | A打开祭坛GUI，B献祭、放材料或取物；A观察数值；再交换角色 | 两端槽内物品、世界悬浮物、LP和进度一致，没有一端永久停留旧画面 |

## 14. 保存、重进、区块与资源重载（D01～D04）

- **D01 正常保存重进**：给祭坛放泥土、炼金台放一组待处理原料、箱子放已绑定球和带小数意志结晶；记录坐标和数量，正常保存退出、重启整个客户端。数据、绑定和数值应保留。
- **D02 合成中退出**：祭坛、阵、炼金台、熔炉分别在部分进度时正常保存退出。重进后完成一次；不能多扣费用、多出产品。因退出过程仍会走少量tick，重进进度略有推进可以正常，不要求精确冻结在截图那个像素。

## 16. 出问题时抓什么：无需自己读懂堆栈

### 16.1 第一时间做的事

1. 记下当地时间到秒、用例编号、世界名、维度和方块坐标；例如 `2026-10-25 22:30:15 +08:00 / A03 / 左键点击祭坛槽后物品回弹`。
2. 能操作时先截图/录屏，再保存退出；崩溃时保存错误窗口和启动器退出码。若完全卡死，记录卡住多久以及是否强制结束进程。
3. **在再次启动游戏之前复制当前日志。** `latest.log` 会随新运行更新，复现次数多时容易把出事那次覆盖掉。
4. 不要求你定位哪一行是原因。提供完整原文件或ZIP，保留最初加载、模组版本和异常前后上下文。
5. 非崩溃图形错误经常没有ERROR；“日志没报错”不能否定鼠标偏移或贴图问题，所以截图/视频必需。

### 16.2 日志路径怎么找

以启动器给这个实例配置的**游戏目录**为准，不以启动器程序所在文件夹或随便一个 `.minecraft` 为准。

| 场景 | 常见位置/定位方法 |
|---|---|
| 官方启动器，未自定义目录的Windows Java实例 | `%APPDATA%\.minecraft\`，本机此默认值通常为 `C:\Users\Administrator\AppData\Roaming\.minecraft\` |
| 官方启动器自定义安装配置 | “安装配置 → 对应配置 → 编辑 → 游戏目录”中的实际路径 |
| 第三方启动器、有版本隔离 | 用该实例的“打开游戏目录/实例文件夹”；有的在 `.minecraft\versions\<实例名>\`，有的在 `instances\<实例名>\.minecraft\`，不能统一假设 |
| 本工程Gradle图形客户端 | `D:\GPT\mods\bloodmagic-neoforge\run\`，例如该目录下的 `logs\latest.log` |
| 本工程自动回归服务端 | `D:\GPT\mods\bloodmagic-neoforge\run\stage6-smoke\`；这里的日志是自动测试结果，不是你的外部客户端日志 |
| 独立服务器 | 服务端启动工作目录，里面应有 `server.properties`、`mods`、`logs`；单独收集它的日志 |

若仍找不到：进游戏“选项 → 资源包 → 打开资源包文件夹”，从 `resourcepacks` 返回父目录，通常就是该实例游戏目录；再核对里面 `logs\latest.log` 的修改时间是否对应本次运行。也可以在启动器启动日志里查看 `--gameDir` 参数。

### 16.3 各个文件的用途

| 文件 | 相对 `<游戏目录>` 的路径 | 什么时候发 |
|---|---|---|
| 最新运行日志 | `logs\latest.log` | 所有问题都发，优先完整原文件 |
| 调试日志 | `logs\debug.log` | 存在就一起发；启动器/配置可能未生成，找不到时注明即可 |
| 崩溃报告 | `crash-reports\crash-日期_时间-client.txt` 或 `...-server.txt` | 崩溃必查，挑与发生时间吻合的报告；单人也可能产生server报告 |
| 轮转历史日志 | `logs\日期-序号.log.gz`，或其他实际生成的轮转文件 | 已重启过导致latest被覆盖时，找对应时刻的那份 |
| JVM致命崩溃文件 | 常见 `hs_err_pid数字.log`，可能在游戏目录、启动工作目录或系统临时目录 | 游戏直接消失、原生/驱动/JVM故障，且没有常规崩溃报告时 |
| 启动器日志/控制台导出 | 各启动器位置不同，使用其“导出日志/查看启动日志” | 启动前失败、Java无法启动、无latest、直接退出、需要退出码时 |
| 游戏截图 | `screenshots\` | 使用默认F2截图时通常在这里；也可用系统截图或录屏 |
| 服务端日志 | `<服务端目录>\logs\latest.log`、`debug.log`、`crash-reports\` | 只在联机/服务端问题时与客户端日志成对提供 |

例：标准默认实例的完整路径是
`C:\Users\Administrator\AppData\Roaming\.minecraft\logs\latest.log`。
外部启动器的实例若在 `D:\Minecraft\instances\BMNeo\.minecraft`，应取
`D:\Minecraft\instances\BMNeo\.minecraft\logs\latest.log`，而不是工程 `run` 目录的文件。

没有 `crash-reports` 文件夹不代表没有崩溃；也不需要为了生成它再反复启动。

### 16.4 按症状准备证据

| 症状 | 必留资料 | 额外记录 |
|---|---|---|
| 渲染错位、阵纹不可见、紫黑贴图 | 完整latest；debug如有；俯视和侧视截图；20～30秒走动视频 | 坐标、面向、距离、白天/夜晚、显卡、渲染设置、资源包/着色器、是否只某配方出错 |
| GUI鼠标偏移或点击无反应 | 完整latest；鼠标可见的全窗口视频；GUI截图 | 分辨率、GUI缩放、Windows显示缩放、窗口/全屏、主副手、是否潜行、点击格子、普通/Shift/数字键、背包空位 |
| 合成不动或“扣费了但没出物” | 完整latest；操作前后原料/输出/LP/意志截图 | 配方、材料是否分槽、血球等级与绑定、结构等级、状态文字、是否暂停、是否有其他耗费 |
| 一打开GUI/靠近机器就崩溃 | latest、debug、对应crash报告、退出码、最后一步截图 | 机器ID、坐标、手中物品、有没有第二人打开同一菜单、重进是否立即再崩 |
| 窗口突然消失，无Minecraft报告 | latest、启动器控制台、退出码、hs_err如有 | 运行多久、内存设置、Java路径/版本、显卡/驱动；不能仅凭“Exit code 1”归因 |
| 只有联机出错、断线、物品回弹 | 客户端与服务端同一时段完整日志、断线画面 | 两端JAR哈希/版本、A/B角色、延迟、谁先操作、单人能否复现 |
| 卡死不退出 | 截图/视频、卡死时长、latest/debug、启动器输出 | 是否还能移动鼠标/切窗口、声音是否循环、是否强制结束；不必主动制造一次崩溃 |
| 重进丢物、重复产出、余额异常 | 重进前后截图、退出及重进两次完整日志 | 是否正常保存退出、是否强杀、世界/维度/坐标、此前数量；必要时提供最小复现世界副本 |

**GUI无响应的现场排除顺序**：先确认没按潜行、主副手空 → 在交互距离内 → 未处于旁观模式 → 点击的是合法槽而非文字/进度条 → 检查状态文字和输出是否满 → 看其他普通箱子能否操作 → 截图录像并留日志。不要先删除配置或存档，这会让复现条件丢失。

### 16.5 打一个清楚的反馈ZIP

手动创建一个新文件夹，例如 `BMNeo-A03-20261025-223015`，放入：
